# 10 API & web UI

**Purpose** Deliver the engine as REST + SSE with a chat UI (approved plan: first deliverable).

**API** (`api/app.py`) `POST/GET /api/sessions`, `GET /api/sessions/{id}` (state: phase stepper data, pending approvals with exact content/hash/roles/`can_approve`, evidence, requirements, budget), `POST …/messages` (SSE), `POST …/approvals/{aid}/grant` (role-checked, optional `seen_hash`), `POST …/continue` (SSE), `POST …/mode`, `POST …/resume/{wid}`, `POST …/budget`, `GET /api/board?mode=`, `GET /api/releases`, `GET /api/releases/{id}/issues`, `GET /api/audit` (lead/admin/sre), `GET /api/plugins`, `GET /api/health`. Per-session lock. Auth via `Authenticator` plugin (dev-header locally).
**UI** (`web/`, work-management-style layout with own branding; light/dark) — top nav (Board · Chat · Settings), a **Development / Support** toggle that applies to both views, **＋ Create** dialog, avatar menu (identity/token, sign out).
- **Board** (`GET /api/board?mode=`): a Kanban per mode — Backlog (unrouted chats) + one column per workflow phase (DEV: Intake → PR Approval; SUPPORT: Triage → Outputs). Cards show ticket key, "approval" / "parked" / "handed off" lozenges; click opens the card's chat (parked items are resumed). Read-only by design: phases advance only through the agent's gated workflow, so cards can't be dragged. Scope = the caller's own sessions.
- **Layout:** the left work-item panel appears on the **Chat** tab only; the Board is full width.
- **Releases panel (Board, right side):** `GET /api/releases` lists the tenant's Jira releases (project versions) — unreleased soonest-first with overdue flag and done/total progress, plus recently released; each links to Jira. Uses the Jira integration's default project key (`?project=` overrides), read-only, cached 60 s, free text redacted. States: Jira not connected / no project key / error / empty — the board never breaks if Jira is down.
- **Release dropdown (Board toolbar):** filters the cards to work items whose Jira ticket key is in the chosen release (`GET /api/releases/{id}/issues` → JQL `fixVersion = <numeric id>`, id validated as digits so JQL can't be injected). Also available as "Filter board" on each release in the panel; "Clear filter" resets; the choice is remembered; Backlog (unrouted chats, no ticket) is hidden while filtering. Disabled with a hint when Jira isn't connected. Cards match by exact ticket key (`ref`), so items created without a ticket key never match a release.
- **Chat**: issue-style page — breadcrumb, title, mode/phase/approval lozenges, chevron workflow bar, activity feed (avatars, tag lozenges, gate/denied/flag events, typing indicator), yellow "Action required" panel with the exact artifact + hash + Approve button, details side panel (requirements for DEV, evidence for SUPPORT, budget, parked items).
- **Settings**: left-nav sections (see spec 11). All content via the `h()` DOM builder (`common.js`) — no innerHTML.

**Acceptance → tests** (`tests/integration/test_api.py`) `test_auth_required_and_static_index`, `test_session_is_tenant_isolated`, `test_message_stream_and_state`, `test_viewer_cannot_approve_and_gets_roles`, `test_board_per_mode_columns_and_cards`, `test_releases_endpoint_states`; adapter: `test_jira_releases_sorted_with_progress_and_best_effort`, `test_jira_release_issues_keys_and_validation`.
**Test gaps** The UI was checked by hand in Chrome (board, chat, create dialog, settings) but has no automated browser tests; board is own-sessions only (no team-wide view); no drag-and-drop by design; SSE `continue`; audit endpoint role gate; budget endpoint; concurrent messages to one session; the SSE parser in `app.js`.
**Out of scope** Real login (OIDC), CSRF/session cookies, admin UI for integrations/tenants, notifications.
