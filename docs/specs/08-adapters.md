# 08 Capabilities & adapters

**Purpose** Vendor-neutral tool contracts so workflows work with any provider (A11), plus reference implementations.

**Contracts** `capabilities/__init__.py`: `ticketing`, `source_control`, `design`, `execution`, `metrics`, `logs`, `cluster`, `traces`, `docs`. Each ToolSpec carries capability/access/environment/approval_kind/artifact_arg/bounded.

**Adapters**
- `jira` (REST v3; comment authors omitted): the agent's ticketing tools **and** the board's read/move methods — `resolve_project` (key *or* name → key; a miss lists the projects you can use), `issues` (stories/tasks/bugs; epics reported separately, sub-tasks skipped), `board_columns` (Agile board; falls back to workflow statuses by category), `releases`, `release_issues` (epic-aware), `project_meta` (real types/statuses), `move_issue` (transition by status ids), `transition_to_named` (phase sync: first allowed candidate name; never forces, reopens Done tickets or moves backwards on the board), `ping`.
- `github` (local clone + PR API): commits local until push; never force; path-traversal + protected-branch guards; token via env-config header, not argv/URL; `ping` reports repo reachability, whether the token **can push**, and turns 401/404 into actionable messages. The settings validator normalises `https://github.com/org/name(.git)`, SSH and `org/name` to `org/name`.
- `grafana` (Prometheus proxy, aggregates only), `loki` (limit ≤200, label-injection sanitised), `rancher` (k8s events, GET only), `figma`, `local_exec` (configured commands only, minimal env, `{"passed": bool}`), `mcp_bridge` (only tools tagged in config; stdio or streamable-HTTP; supports MCP SDK 1.x and 2.x), `fake` (tests/demo).
- Shared: `adapters/util.py` (`parse_time_range` ≤7 days, `Http` with lazy credential lookup and a per-request SSRF check).

**Acceptance → tests** (`tests/adapters/test_adapters.py` unless noted) time range/labels: `test_time_range_relative_iso_and_limits`, `test_label_selector_needs_scope_and_escapes`. Jira: `test_jira_get_item_and_comment`, `test_missing_credential_is_a_clear_error`, `test_jira_issues_for_board_maps_fields_and_skips_subtasks`, `test_jira_board_columns_from_agile_board_then_fallback_to_workflow_statuses`, `test_jira_move_issue_uses_workflow_transitions_only`, `test_transition_to_named_*` (first candidate, equivalent fallback, never regresses/reopens/forces), `test_jira_releases_sorted_with_progress_and_best_effort`, `test_jira_release_issues_keys_and_validation`, `test_release_filter_includes_work_under_an_epic_that_carries_the_release`, `test_jira_project_name_resolves_to_key_and_wrong_project_lists_choices`, `test_project_meta_reports_types_and_statuses_in_board_order_without_epics`. Others: `test_loki_bounded_and_limited`, `test_commits_stay_local_until_push_and_protected_refused`, `test_open_pr_uses_api`, `test_github_ping_*`, `test_local_exec_reports_pass_fail_and_only_configured_tools`, `test_mcp_only_exposes_tagged_tools_with_gates`, and `test_mcp_bridge_end_to_end_against_a_real_server` (a real stdio MCP server, in `tests/integration/test_admin.py`).

**Verification status** Jira was also exercised read-only against a real Jira Cloud project (project resolution, statuses/board columns, types, releases, epic-aware release filter); drag/moves and phase sync were exercised against a Jira-like mock with a real workflow, not against real Jira. All other HTTP adapters are tested against mocked responses.
**Test gaps** Grafana, Rancher, Figma adapters; Jira `create_items`/`search`; GitHub merge/delete/search/diff; real-API smoke tests for everything except Jira reads.
**Out of scope** Datadog/PagerDuty/GitLab adapters; OAuth flows; per-adapter retries/backoff.
